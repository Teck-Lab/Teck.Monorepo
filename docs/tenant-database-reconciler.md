# Tenant database reconciler contract

The backend `TenantDatabase.Reconciler` currently provides a durable request store, Billing RSA-verified paid-event intake, polling worker, Kubernetes CNPG adapter and unit-tested reconciliation state machine. `SignedTenantDatabaseIntake` binds the immutable source order and proof before storing dedicated desired state; a changed replay is rejected. It is **not an executable deployed worker**: no production host subscribes to the signed Billing payment/suspension events or publishes database readiness yet. Do not insert desired state from an unauthenticated caller or claim a tenant ready from this library alone.

Only paid dedicated PostgreSQL tenants belong in the reconciler-managed `tenant-databases` namespace. Tenant resource names derive from the Customer registry UUID, never a caller-supplied slug. The existing `postgres` namespace cluster belongs to Argo/GitOps and must never be modified. Namespace-scoped service-account permissions and the production image/deployment belong to Teck.GitOps #7, blocked on the backend image and complete contract.

The chosen dedicated topology is **per-service tenant databases** for `basket`, `catalog`, `inventory`, `order` and `pricing`. Each routed service owns its own EF migrations and its `/tenants/{tenantIdentifier}/{serviceName}` OpenBao KV v2 `write`/optional `read` secret. Customer (including profiles and the global tenant registry) remains on its global database for now; Billing remains the global order/payment authority. A single CNPG healthy phase or credentials Secret is not proof that all five service databases have been migrated and their PostgreSQL roles exist. The worker must create/revoke both database roles and OpenBao secrets and verify migration completion for every participating service before emitting Billing-correlated, producer-signed database readiness. A healthy CNPG Cluster must have a real Kubernetes resource UID, and a CNPG `Database` must report `status.applied: true` with `status.observedGeneration` equal to its `metadata.generation` (per CNPG 1.28 declarative Database API). A mocked phase or unsupported `Ready` condition is insufficient.

On cancellation, Customer denies routing and clears readiness immediately. The reconciler must also revoke database logins and OpenBao access before recording access suspended; a Kubernetes JSON merge patch with `data: {}` **preserves existing credentials**. The current backend therefore fails closed when a credential-bearing Secret is still present. Suspended resources remain retained even after the proposed 30-day recovery window; **no automatic purge** runs. An approved, signed tenant-specific deletion request and verified recoverable backup must gate a separate destructive path before `Purged` can be reported. An unsigned or wrong-tenant request must never delete resources, and no production data removal is authorized by the current code.
